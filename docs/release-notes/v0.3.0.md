Windows, a way to upgrade from inside the tool, and the Checks tab finished.

## New

**Windows is a supported platform.** There is a PowerShell installer now, and
the release carries Windows on arm64 and amd64 beside macOS and Linux. It checks
the download against the release's checksums the way the POSIX script does, and
puts the binary in `%LOCALAPPDATA%\Programs\zen-octo`. Through v0.2.0 the only
route was taking the `.zip` off the release page by hand. The test suite runs on
Windows in CI as well, so the platform stays supported rather than built.

**`zen-octo update` installs the latest release over the running binary.** It
asks GitHub what the latest release is, stops if you already have it, and
otherwise runs the installer for your platform into the directory the running
binary sits in. A binary built from a clone reports `dev` and is replaced by the
latest release, so stay on `make install` if you want your own build.

**The status bar names a newer release when one is out.** A check at launch, at
most one request a day, cached under `~/.zen-octo`. The request carries no token
and a failed one shows nothing. `updateCheck: false` turns it off.

**`v` marks a range in the diff.** It drops an anchor on the row under the
cursor, and moving the cursor runs the selection from it. `v` again clears it,
and so does `esc`, leaving the hunk, or stepping to the other column. A comment
is still scoped to the cursor's own line.

**A workflow's own row reruns the whole run.** `r` reruns what failed in it, `R`
reruns all of it. On a single job `r` still reruns that job. Every job a rerun
will replace is marked while the call is out, so a bulk rerun reads the way one
job's does.

**`⏎` on a check in the details rail opens it on the Checks tab**, which is the
tab holding its log and its rerun keys. That row drew and lit with nothing
behind it before.

## Changed

**`⏎` is the jump from a review comment to the code it was written against.**
`v` did that through v0.2.0 and now selects lines in the diff instead.

**The diff washes and the cursor line come from your palette.** The green, the
red and the lift under the selected row are derived from the background your
terminal reports rather than written down, so they sit just above it whether it
is light or dark. `addedBackground`, `removedBackground` and `selectedBackground`
override them where a terminal lands somewhere odd.

## Fixed

- `transparent: true` meant "paint nothing" and took the cursor line and the
  diff washes with it, which left the pull request list, the pickers, the file,
  commit and check columns and the merge form with no cursor at all. It now
  withholds the background and nothing else.
- A check that failed with no log to read was offered `f` anyway, and the Checks
  hints dropped on every step of the job column.

## Install

macOS and Linux:

```sh
curl -fsSL https://raw.githubusercontent.com/praxis-labs-io/zen-octo/main/install.sh | sh
```

Windows:

```powershell
irm https://raw.githubusercontent.com/praxis-labs-io/zen-octo/main/install.ps1 | iex
```

Each platform on arm64 and amd64, with no Go needed. Both installers check the
download against this release's `checksums.txt` and install nothing that does
not match. `INSTALL_DIR` overrides where the binary lands and `VERSION` pins a
release. Already running zen-octo:

```sh
zen-octo update
```

It rides on the [GitHub CLI](https://cli.github.com)'s token rather than asking
for one of its own, so if `gh auth status` is happy, so is zen-octo. Where a
scope is missing it says which and prints the `gh auth refresh` line.

[Install](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/install.md),
[the guide](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/guide.md),
[the keymap](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/keys.md),
and [configuration](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/configuration.md).

## Known gaps

- No submitting a review, checking a branch out, or listing issues. Those still
  go through `gh` or the browser.
- A marked range is read rather than written against. A comment lands on the
  cursor's line.
- No Homebrew tap.
- Neither installer edits your `PATH`. It says so and gives you the line.
- The POSIX installer needs `sha256sum` or `shasum` on PATH, and refuses where
  neither is.
- Under 56 by 23 the shell draws its size instead of a screen, and drops every
  key but the ways out.
