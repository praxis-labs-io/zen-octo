The chrome comes from your terminal now, and the pull request screen has been
rebuilt around the details rail.

## New

**zen-octo takes its colors from your terminal.** The hues are ANSI slots, so
the accent, the check marks and the diff markers are the ones your palette
already uses. The greys, the borders and the cursor line are blended from the
background your terminal reports at startup, so they sit just above it whether
it is light or dark. There is no theme to pick and nothing to configure to get
this.

`theme:` in the config is a set of overrides for the colors it got wrong rather
than a name. `background` and `foreground` are what everything else is derived
from, which is also the way out for a terminal that cannot answer the query:
`screen`, and some `tmux` and `ssh` setups, never reply. `transparent: true`
paints nothing, for a window running translucent. `syntaxTheme` names the
palette code is highlighted with, that being the one thing that cannot follow
your terminal.

A config still saying `theme: rose-pine-moon` starts and says so rather than
refusing.

**`/` searches the list.** It narrows the section on screen against the number,
the repository, the title, the author and the head branch, reading what is
already fetched rather than asking GitHub. `⏎` keeps the filter and hands the
keyboard back, `esc` clears it, and the bar stays up while a filter stands with
what it matched counted against the section.

## Changed

**The details rail is down the left.** Every secondary pane is that column now,
so the sidebar no longer changes sides on a keypress that only changed which tab
was on. It takes the keys on the way in, and each tab gives back the pane you
left it on.

**The header is two lines.** The title and the number lead, with what the pull
request changes at the far edge; the branches lead the second, with the
lifecycle and the check rollup at the far edge of that. Who opened it moved to
the status bar. That far edge sheds a group at a time as the frame narrows,
where before the title was the half giving way.

**The tab strip sits on a row of its own**, under the header and above the
panes, with a count on each tab and an underline under the current one.

**A cursor is landed wherever there is something to land it on**, so the first
press of a motion key moves rather than arrives, and `esc` leaves in one press.

**`tab` and `shift+tab` step the column that drives the pane**: the file on
Files, the commit on Commits, the check on Checks. `]` and `[` are the tab keys
on both screens.

**The hint line names only the keys that answer** where you are standing, and
sheds whole hints from the right as the line narrows rather than cutting one in
half. `?` is the last to go. `q` came off it, being the most guessable key in a
terminal program and on the overlay besides.

**Every text box reports its caret and the terminal draws it.** One cursor, one
shape, blinking in the emulator rather than by redrawing the frame it sits in.

## Fixed

- The Checks hints dropped on every step of the job column and came back a round
  trip later. `f` is now offered on a check that failed and has a log to jump
  into, rather than on any check that failed.
- A stacked pull request puts a branch name on both sides of the arrow, and the
  header clipped the head to fit. The two names share the row, and a name that
  fits is never cut.
- The mention popup opened two panes from the word it was answering, once the
  rail moved left.
- The merge headline pinned its cursor to the right edge past the width of the
  box. It wraps instead.
- `/` over a section that was empty anyway answered by blaming a search nobody
  had typed.

## Install

```sh
curl -fsSL https://raw.githubusercontent.com/praxis-labs-io/zen-octo/main/install.sh | sh
```

macOS and Linux, arm64 and amd64. Windows takes the `.zip` from this page, the
installer being a POSIX script. `INSTALL_DIR` overrides where it lands and
`VERSION` pins a release. Anything else:

```sh
go install github.com/praxis-labs-io/zen-octo/cmd/zen-octo@v0.2.0
```

It rides on the [GitHub CLI](https://cli.github.com)'s token rather than asking
for one of its own, so if `gh auth status` is happy, so is zen-octo. Where a
scope is missing it says which and prints the `gh auth refresh` line.

[Install](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/install.md),
[the guide](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/guide.md),
[the keymap](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/keys.md),
and [configuration](https://github.com/praxis-labs-io/zen-octo/blob/main/docs/configuration.md).

## Known gaps

- No Homebrew tap.
- No approve, no request changes, no checkout, and no issues view. Those still
  go through `gh` or the browser.
- The two diff tints are a standard green and red wash rather than your own
  palette's. A terminal reports what a slot is named, not what it maps to.
- Under 56 by 23 the shell draws its size instead of a screen, and drops every
  key but the ways out.
